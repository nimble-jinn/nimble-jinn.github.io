Notes from the build.

Notes from the people building Farholm. Irregular, technical, and honest about what is not working.

2026-08-13

A skeleton before any flesh

The rule we set for ourselves at the start of Farholm was that the whole skeleton gets built before any of it gets flesh. Every screen the game will need exists and is reachable, every one of them shows real data from the real model, and none of them are pretty yet.

It is a slower-feeling start and a much faster middle. The alternative — building one beautiful vertical slice and discovering six months later that the shape underneath it was wrong — is the failure mode we have watched happen to other projects, and to be honest, been part of once or twice.

So: identity and profiles, the hub, run setup with a seed you can type in, the star map, settings, inventory, marketplace. All connected, all reading from real state, all deliberately plain. The persistence layer writes locally first and syncs when there is somewhere to sync to, which means the game works with the network off — a property we would rather design in than retrofit.

The one piece we refused to build speculatively was a confirmation dialog. Nothing in the skeleton had asked for one yet. It can wait until something does.

More as it happens.

We post when there is something worth saying, which is not every week.
